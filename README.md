# Navigator with interesting voices

Навигатор с персональным голосом: пользователь записывает образец речи, а приложение озвучивает новые навигационные команды узнаваемым голосом. Главная идея — услышать свою речь в маршруте, включая фразы, которые никогда не были записаны заранее.

## Статус

Проект находится на этапе **голосового MVP**. Первая рабочая среда — Windows-ПК с NVIDIA GPU. Здесь проверяется локальный синтез; следующий продуктовый этап — Android-приложение с базовым дизайном, картой и симуляцией поездки.

Локальная **Qwen3-TTS 0.6B Base** уже загружается на GPU и генерирует аудио. Проверены целостность весов, два технических режима генерации и 40 автоматических тестов. Качество клонирования конкретного человека пока не подтверждено: для этого нужен отдельный прогон на его записи с прослушиванием результата.

HTTP-бэкенд, база голосовых профилей и Android-клиент ещё не реализованы. Карта и полноценная GPS-навигация относятся к последующим этапам.

На GitHub пока публикуется только этот README. Исходники, архитектурные документы и рабочие отчёты остаются в локальной рабочей папке. Команды ниже описывают текущую среду разработки; одного клонирования публичного репозитория для запуска недостаточно.

## Базовый принцип

Голос и текст команды — разные входные данные. Модель получает образец речи с точной расшифровкой и произносит новый текст; готовая фраза не собирается из записанных отдельных слов.

```text
образец голоса + расшифровка → локальная модель → новый текст → аудиофайл
```

При синтезе записи остаются на ПК. API-ключи и оплачиваемый облачный сервис для текущего эксперимента не нужны. После первоначальной загрузки модели генерация работает offline и использует ресурсы компьютера.

Для клонирования предполагается собственный голос либо голос человека, разрешившего его использование.

## Локальная голосовая лаборатория

В рабочей папке `tools/voice-lab` подготовлены три части:

- **Проверка записи:** реальный формат WAV, длительность, тишина, низкий уровень сигнала и перегрузка.
- **Локальный синтез:** выбор тестовой фразы, обработка образца и расшифровки, сохранение результата и отчёта.
- **Технические тесты:** проверка обработки файлов, ошибок и генерации на GPU без использования чужих голосов.

Каждый запуск сохраняет отдельный результат в `data/voice-lab/`: WAV и JSON-отчёт со временем загрузки, генерации, длительностью аудио и расходом видеопамяти. Повторный запуск не перезаписывает предыдущий результат. Автоматические повторы генерации не выполняются.

Модель, её кэш, личные записи и сгенерированное аудио хранятся в `data/` и не публикуются.

## Текст для первой записи

Для первого опыта достаточно спокойной записи примерно на 15–20 секунд. Нужно говорить обычным голосом, без музыки и других людей на фоне:

> Сегодня я решил рассказать о привычных вещах, которые делают день приятнее. Утром я открываю окно и прислушиваюсь к звукам улицы. Мне нравится начинать день без спешки, приготовить завтрак и подумать о планах.

Тот же текст в локальной рабочей папке: `fixtures/phrases/reference-short.ru.txt`. Подробная инструкция и длинный вариант: `fixtures/phrases/recording.ru.md`.

Первый инструмент принимает **WAV PCM 16 бит**, один или два канала, 16–96 кГц. Для синтеза используется образец длиной 3–30 секунд. Файл можно сохранить как `data/samples/my-voice.wav`. При оговорках нужно перезаписать фрагмент или подготовить точную расшифровку в отдельном TXT.

Проверка записи из корня локального проекта:

```powershell
npm run voice:lab -- inspect --sample data/samples/my-voice.wav
```

Проверка параметров файла не определяет узнаваемость голоса, разборчивость речи или наличие эха — эти свойства оцениваются прослушиванием.

## Генерация новой фразы

На текущем ПК используется окружение `data/voice-runtime-existing`. После подготовки своей записи:

```powershell
data/voice-runtime-existing/Scripts/python.exe tools/voice-lab/local.py synthesize --sample data/samples/my-voice.wav --transcript fixtures/phrases/reference-short.ru.txt --phrase turn-right --consent
```

Флаг `--consent` подтверждает право использовать запись. В этом примере модель должна произнести: «Через 300 метров поверните направо».

Отдельный набор содержит восемь фраз для проверки расстояний, чисел, названий улиц, пауз и завершения поездки. Доступные фразы и состояние локального инструмента:

```powershell
npm run voice:lab -- phrases
npm run voice:doctor
```

## Автоматические проверки

Быстрые тесты не скачивают модель и не обращаются к платным API:

```powershell
npm test
py -3.11 -m unittest discover -s tools/voice-lab/test -p 'test_*.py' -v
```

Проверки с настоящими аудиобиблиотеками и подставным генератором:

```powershell
data/voice-runtime-existing/Scripts/python.exe -X utf8 -m unittest discover -s tools/voice-lab/runtime-test -v
```

Сейчас проходят **16 Node-тестов, 19 Python-тестов и 5 runtime-тестов**. Они проверяют повреждённые файлы, загрузку весов частями, контрольные суммы, расшифровку, порядок инициализации CUDA, сохранение аудио и обработку ошибок.

Отдельный `runtime-smoke` запускает настоящую модель с синтетическим сигналом. На RTX 4060 Ti с 8 ГБ памяти технический режим «аудио + расшифровка» показал:

| Измерение | Результат |
| --- | --- |
| Загрузка модели | 8,66 с |
| Генерация короткого результата | 3,99 с |
| Длительность результата | 2,48 с |
| Пик выделенной GPU-памяти | 2275 MiB |

Это один технический прогон с ограничением в 32 выходных токена. Он подтверждает работоспособность вычислений, но не качество речи и не скорость озвучивания произвольного маршрута.

## Технологии

| Часть | Технологии | Состояние |
| --- | --- | --- |
| Локальная генерация | Python 3.13, PyTorch 2.7.1 + CUDA 11.8, Qwen3-TTS 0.6B Base | Технический запуск проверен |
| Проверка WAV и тестовые команды | Node.js 24, ES-модули, встроенный test runner | Реализовано |
| Проверки Python | unittest, NumPy, SoundFile | Реализовано |
| HTTP-бэкенд | TypeScript, Fastify, Zod, OpenAPI | Запланировано |
| Профили и задачи | PostgreSQL, Drizzle | Запланировано |
| Android | React, TypeScript, Capacitor | Предварительный выбор |
| Карта и маршруты | MapLibre, MapTiler, GraphHopper | Кандидаты для проверки |

В текущем окружении проекта повторно используются уже установленные CUDA-библиотеки. Переносимость установки на другой ПК ещё предстоит подтвердить отдельно.

## Следующие этапы

1. Проверить узнаваемость голоса и произношение новых фраз на собственной записи.
2. Реализовать HTTP API, хранение голосовых профилей, очередь задач и обработку сбоев.
3. Подключить Android: запись с микрофона, выбор голоса и тестовое прослушивание.
4. Добавить карту, симуляцию поездки и подготовку навигационной озвучки заранее.
5. Отдельно рассмотреть браузерную версию.

Настольное приложение не планируется: ПК служит средой разработки и проверки бэкенда. Пробки, офлайн-карты, фоновые GPS-сценарии и полноценная картографическая платформа не входят в текущий MVP.
